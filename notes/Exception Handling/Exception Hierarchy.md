# Exception Hierarchy in Java

Exceptions represent abnormal situations that occur during program execution.

Java provides a hierarchy for handling these abnormal conditions.

---

# Exception Hierarchy

```text
Object
   ↑
Throwable
   ├── Exception
   │      ├── Checked Exceptions
   │      └── Unchecked Exceptions (Runtime Exceptions)
   │
   └── Error
```

---

# Object Class

Every class in Java implicitly extends:

```java
java.lang.Object
```

Example:

```java
class Bank {

}
```

Behind the scenes:

```java
class Bank extends Object {

}
```

Therefore every class gets methods like:

```java
toString()
equals()
hashCode()
```

---

# Throwable Class

```java
java.lang.Throwable
```

is the parent class of:

- Exception
- Error

It represents anything that can be thrown using:

```java
throw
```

---

# Throwable Hierarchy

```text
Object
   ↑
Throwable
   ├── Exception
   └── Error
```

---

# Exception

Exceptions generally occur because of problems in our code.

These situations are recoverable.

Examples:

- File not found
- Invalid input
- Database connection issues
- Null references
- Array index problems

---

# Error

Errors are serious problems.

Usually they are beyond the control of application code.

They are generally generated by:

- JVM
- Memory issues
- System failures

Errors are considered dangerous and usually not handled.

Examples:

- OutOfMemoryError
- StackOverflowError
- VirtualMachineError

---

# Exception Types

```text
Exception
    ├── Checked Exception
    └── Unchecked Exception
```

---

# Checked Exceptions

Checked exceptions are verified by the compiler.

They must be either:

- handled using try-catch
- or declared using throws

---

### FileNotFoundException

```java
FileInputStream fis =
```

Compiler forces handling.

---

### SQLException

```java
Connection connection = DriverManager.getConnection(url);
```

# Unchecked Exceptions

Unchecked exceptions are also called:

```text
Runtime Exceptions
```

Compiler does not force handling.

They occur during program execution.

---

# Examples

## ArrayIndexOutOfBoundsException

```java
int[] arr = {10,20,30};

System.out.println(arr[5]);
```

Output:

```text
ArrayIndexOutOfBoundsException
```

Because index 5 does not exist.

```java
String name = null;
```

Output:

```text
NullPointerException
```

---

## ArithmeticException

```java
int result = 10 / 0;
```

Output:


Output:


# Error Hierarchy

# Example of StackOverflowError

```java
public static void display() {

    display();
}
```

Infinite recursion causes:

```text
StackOverflowError
```

---

# Example of OutOfMemoryError

```java
List<Integer> list = new ArrayList<>();

while (true) {

    list.add(1);
}
```

Eventually memory gets exhausted.

Result:

```text
OutOfMemoryError
```

# Checked vs Unchecked Exceptions

| Feature | Checked Exception | Unchecked Exception |
|----------|-----------------|--------------------|
| Checked By Compiler | Yes | No |
| Occurs | Compile Time | Runtime |
| Mandatory Handling | Yes | No |
| Parent Class | Exception | RuntimeException |
| Examples | IOException, SQLException | NullPointerException, ArithmeticException |

---

# Exception vs Error

| Exception | Error |
|------------|------|
| Recoverable | Serious problem |
| Due to application code | Due to JVM/System |
| Can be handled | Usually not handled |
| Child of Exception | Child of Error |
| Less dangerous | More dangerous |

---

# Example

```java
try {

    int result = 10 / 0;

} catch (ArithmeticException e) {

    System.out.println("Handled");
}
```

Output:

```text
Handled
```

---

# Why Exception Handling?

To avoid abnormal program termination.

Without handling:

```java
System.out.println("Start");

int result = 10 / 0;

System.out.println("End");
```

Output:

```text
Start

ArithmeticException
```

Program terminates.

---

With exception handling:

```java
System.out.println("Start");

try {

    int result = 10 / 0;

} catch (ArithmeticException e) {

    System.out.println("Exception handled");
}

System.out.println("End");
```

Output:

```text
Start
Exception handled
End
```

Program continues normally.

# Interview Questions

## Q1. What is the root class for exception handling?

```java
Throwable
```

---

## Q2. What are the direct subclasses of Throwable?

```java
Exception
Error
```

---

## Q3. What are checked exceptions?

Exceptions verified by the compiler.

Examples:

- IOException
- SQLException
- FileNotFoundException

---

## Q4. What are unchecked exceptions?

Runtime exceptions that are not checked by the compiler.

Examples:

- NullPointerException
- ArrayIndexOutOfBoundsException
- ArithmeticException

---

## Q5. What is the parent class of all unchecked exceptions?

```java
RuntimeException
```

---

## Q6. What is the difference between Exception and Error?

Exceptions are recoverable.

Errors are serious problems generally caused by JVM or system resources.

---

## Q7. Is NullPointerException checked or unchecked?

Unchecked.

Because:

```text
NullPointerException
    ↑
RuntimeException
    ↑
Exception
```

---

## Q8. Is FileNotFoundException checked or unchecked?

Checked.

Compiler forces handling.

---

## Q9. Can Errors be caught?

Yes.

```java
catch (Error e)
```

is possible.

But generally not recommended because errors indicate severe problems.

---

# Key Takeaways

- Every class ultimately extends `Object`.
- `Throwable` is the root class of exception handling.
- `Throwable` has two children:
  - `Exception`
  - `Error`
- Exceptions are caused by application code and are recoverable.
- Errors are severe JVM/system problems.
- Exceptions are divided into:
  - Checked exceptions
  - Unchecked exceptions
- Runtime exceptions are unchecked exceptions.
- Checked exceptions are verified by the compiler.
- Runtime exceptions occur during execution.
- Exception handling prevents abnormal termination of programs.
